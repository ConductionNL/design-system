Protection

What the server refuses, how large and how fast mail may be, and when it insists on encryption. Changes apply to every domain on this server as soon as you save.

Incoming mail

Checks on the sending server before a message is accepted. Together they stop most spam before anyone sees it.

A server we have not seen before is asked to try again in a few minutes. Real mail servers do, most spam senders do not.
The sending address is looked up in these DNS block lists. A listed server is refused before the message is read.

The sender address must belong to a domain that can receive mail. Forged addresses from made-up domains are refused.

Encryption and relay

When the server insists on encryption, for people signing in and for other mail servers.

Require encrypted connectionsApplies to everyone who signs in: the browser, phones and other mail programs.
A password sent in the clear can be read on the way. An old mail program set to plain text gets a clear error instead.
Strict: some small servers still deliver without encryption. Last 7 days: 3 of 6,120 messages, all from stadtwerke-kassel.example.
Only signed-in people and your own network can send mail through this server to the outside. An open relay is blocked by other servers within hours.
Outgoing connections to other serversHow this server talks to the server that receives your mail.
Every outgoing message goes to the relay of your hosting provider, which has a known reputation, instead of to each receiving server.
Every other server this one talks to must show a certificate that a known authority signed. Off only for testing; it lets anyone pose as the other server.
What the server fetches on a person's behalf, such as remote images, may not point at addresses inside your own network.
