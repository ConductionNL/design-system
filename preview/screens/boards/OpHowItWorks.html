How it works

One catalogue, two standalone tools, one file between them

Thematiq styles Nextcloud, the OpenProject plugin styles OpenProject. Nothing links them at runtime: a design system travels between them as a file, and a pixel check keeps both shells on the same canon.

1

One catalogue of design systems

Thematiq owns the mapping. The plugin ships a bundled copy generated from it, so both offer the same list.
  • Northwind house style
  • OpenProject example
  • Zuiddrecht
  • Cunningham
2

thematiq

Nextcloud app, standalone Nextcloud
  • Picker
  • Style editor
  • Export and import
  • Figma upload and download
2

OpenProject plugin

Ruby gem, standalone OpenProject
  • Picker
  • Style editor
  • Export and import
  • Figma upload and download

A design system is a file

W3C design tokens or Tokens Studio. Export on one side, import on the other. Figma reads and writes the same files.
3

Nextcloud

Thematiq applies the design system to Files, Mail, Calendar, Tasks and the apps
3

OpenProject

The plugin applies it to work packages, Gantt, boards and meetings
4

Pixel check per release

For every OpenProject release the shell and primitives of both products are rendered and compared with the canon. A difference is fixed in the plugin before it ships.

Identical to the pixel

Top bar, navigation, type, colours, buttons, inputs, selects, dialogs, tables, tabs, badges and status dots. A user moving from one product to the other sees no difference in the shell.

Built from the same primitives

Gantt, the work package table, boards, team planner and backlogs have no Nextcloud counterpart. They use the shared buttons, inputs, tables and colours, and are not matched pixel for pixel.
